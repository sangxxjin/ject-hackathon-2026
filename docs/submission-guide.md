# 젝커톤 서비스 소개 및 결과물 제출 가이드

심사위원은 발표 없이 제출된 서비스를 직접 써 본다. 소개 자료는 그 전에 아래 질문에 답할 수 있어야 한다.

- 어떤 서비스인가
- 누구를 위한 서비스인가
- 어떤 문제나 상황에서 출발했는가
- 사용자는 어떤 경험을 하는가
- 실제로 어떤 기능을 구현했는가
- AI를 어떻게 활용했는가

사업계획서가 아니다. 시장 규모, 수익 모델, 경쟁사 분석은 없어도 된다.

이 레포의 소개 페이지는 `/intro` 이다.

| 제출 대상 | 젝커톤 참가팀 전체 |

| 제출 담당 | 팀 대표자 1명 |
| 제출 일시 | 2026년 11월 14일(토) |

| 제출 방법 | 젝커톤 결과물 제출폼 |
| 심사 시간 | 17:30~18:00 |

필수 제출물 3개.

1. 서비스 공개 URL. 심사위원이 설치나 권한 요청 없이 브라우저에서 핵심 기능을 쓸 수 있어야 한다. 로그인이 필요하면 공개 가능한 테스트 계정을 적는다. 앱이면 웹에서 열리게 호스팅한다.
2. 서비스 대표 썸네일. 600×400px, 3:2 이미지 1장. 제출폼으로 올린다.
3. 서비스 소개 자료 URL. PDF, 노션, 이 서비스의 `/intro` 처럼 링크만으로 열려야 한다.

## 소개 자료 필수 항목

| 항목 | 작성 내용 | 권장 분량 |
| --- | --- | --- |
| 서비스명 및 한 줄 소개 | 이름과 핵심 아이디어 | 1문장 |
| 타깃 사용자 | 누가 쓰는가 | 1~2문장 |
| 해결하려는 문제 또는 상황 | 어떤 행동, 감정, 불편에서 출발했는가 | 2~3문장 |
| 핵심 사용자 경험 | 무엇을 하고 어떤 결과를 얻는가 | 3~5단계 |
| 주요 기능 | 실제 서비스에 구현한 기능 | 3~5문장 |
| AI 활용 방식 | 제작 과정과 서비스 안에서 AI를 어떻게 썼는가 | 2~3문장 |
| 기술 스택 및 인프라 | 핵심 스택 | 5~10개 |

소개 자료 안에 대표 썸네일(600×400, 3:2)도 포함한다.

## 작성 템플릿

```text
[서비스명]

한 줄 소개
우리 서비스는 [타깃 사용자]가 [특정 상황]에서 [핵심 경험]을 할 수 있도록 돕는 서비스입니다.

1. 타깃 사용자
2. 해결하려는 문제 또는 상황
3. 핵심 사용자 경험
4. 주요 기능
5. AI 활용 방식
   - 기획 / 디자인 / 개발 / 서비스 기능
6. 사용한 기술 스택 및 인프라
7. 서비스 URL
```

공유 설정은 링크가 있는 사람이 로그인 없이 볼 수 있어야 한다. 노션은 웹 게시, 피그마와 구글 슬라이드는 링크 보기, PDF는 열람 가능한 주소.

## 제출 순서

1. 배포된 주소에서 실행, 핵심 기능, 외부 접근, 테스트 계정을 확인한다. 개발 서버만 되면 안 된다.
2. 위 필수 항목으로 소개 자료를 만든다.
3. 팀 대표 1명이 공식 제출폼을 낸다.
4. 팀별 프로덕트 공개 모음집에 3~5분 안에 반영된다. 직후 빈 페이지는 정상이다.
