# GAP

**선수와 나 사이의 GAP, 오늘 운동으로 좁히세요.**

GAP은 같은 나이의 선수와 나 사이의 차이를 뜻합니다. 그 차이를 보고 좌절하는 대신, 지금 운동할 동기로 바꾸자는 이름입니다.

나이와 응원하는 종목만 넣으면, 같은 나이에 그 종목 선수가 뭘 해냈는지 VAR 판독으로 보여줍니다. 충격받은 당신에게 위로, 동기부여, 독설 중 하나를 고르게 하고, 마지막에는 오늘 10분 안에 할 수 있는 운동 처방과 공유용 선수 카드를 줍니다.

> 세상에서 가장 쓸데없는 비교로 시작해서, 오늘 밖으로 나갈 이유 하나로 끝나는 스포츠 서비스입니다.

## 한 줄 소개

우리 서비스는 **스포츠를 좋아하는 20~40대 팬**이 **"그 나이에 걔는 뭘 했지?" 하고 선수와 나를 비교하게 되는 순간**에, **충격 → 감정 선택 → 오늘의 운동 처방**으로 이어지는 경험을 할 수 있도록 돕는 서비스입니다.

---

## 1. 타깃 사용자

- 야구, 축구, NBA, e스포츠(LoL) 같은 종목을 응원하는 20~40대 팬. 선수 나이를 보고 "내가 저 나이에 뭐 했더라" 하고 한 번쯤 자기와 비교해 본 사람.
- 스포츠를 잘 몰라도 괜찮습니다. "아무거나"를 고르면 됩니다.

## 2. 해결하려는 문제 또는 상황

- 응원하는 선수가 나보다 어린 나이에 우승하고 국가대표가 된 걸 보면, 동경과 질투, 약간의 자기비하가 함께 옵니다. 다들 한 번쯤 해봤지만 아무도 대놓고 꺼내지 않는 감정입니다.
- 이런 비교는 보통 "나는 뭐 하고 살았나"로 끝나고 아무 행동으로도 이어지지 않습니다.
- 우리는 이 쓸데없는 비교를 장난으로 꺼내 웃게 만들고, 그 끝을 **오늘 실제로 몸을 움직이는 작은 행동**으로 바꾸고 싶었습니다.

## 3. 핵심 사용자 경험

1. **입력 두 번** — 응원하는 종목을 고르고 나이를 넣습니다. 로그인도 회원가입도 없습니다.
2. **VAR 판독** — "나이 확인 중", "동갑 선수 대조 중"… AI가 문구를 쓰는 몇 초를 축구 VAR 판독 연출로 채웁니다. 기다림이 곧 콘텐츠입니다.
3. **충격의 리빌** — "○○○는 당신 나이에 월드컵 결승에서 골을 넣었습니다." 1초 정적 뒤에 붉은 글씨로 **"…당신은요?"**. 이 종목 평균 은퇴 나이까지 남은 시간, 내가 태어난 해에 그 선수가 몇 살이었는지도 함께 보여줍니다.
4. **감정 선택** — 지금 필요한 걸 내가 고릅니다. **위로**(같은 나이에 무명·부상을 겪고 나중에 성공한 진짜 선수 이야기), **동기부여**(선수의 실제 훈련 습관), **신랄한 비판**("이 앱 볼 시간에 나가서 뛰세요").
5. **행동과 공유** — 선수의 실제 훈련량을 일반인이 10분 안에 할 수 있게 줄인 **오늘의 처방**을 받고, 질문 4개에 답해 **내 선수 카드(OVR, 등급, 능력치)**를 받아 이미지로 저장합니다. 친구 나이로 한 번 더 돌려볼 수 있습니다.

## 4. 주요 기능

- **동갑 선수 판독**: 종목과 나이를 넣으면 팀이 검증한 선수 기록 중 나이가 가장 가까운 기록을 찾고, AI가 그 기록으로 위로·동기부여·독설 문구를 그때그때 새로 씁니다. 6개 종목(야구, 해외야구, 축구, 해외축구, NBA, e스포츠)과 "아무거나", 10~60세 어떤 조합이든 결과가 나옵니다.
- **VAR 판독 연출과 리빌**: 응답 대기 시간 동안 단계별 판독 문구와 진행 바, "판정 완료" 도장 뒤에 기록이 하나씩 드러납니다. 은퇴 카운트다운과 생년 모드로 나이 비교를 한 번 더 뒤집습니다.
- **3가지 모드 + 오늘의 처방**: 한 번의 AI 응답에 위로, 동기부여, 독설 문구와 운동 처방이 모두 담겨 있어 모드를 바꿔도 기다리지 않습니다.
- **선수 카드**: 질문 4개(계단, 알람, 운동 약속, 응원팀 역전패)의 답과 나이로 체력·의지·변명·멘탈과 OVR을 계산하고, 소파 → 벤치 → 후보 → 주전 → 에이스 등급 카드를 PNG로 저장합니다.
- **멈추지 않는 판독**: AI가 실패하거나 9초 안에 답하지 못하거나 문구 검증에 걸리면, 팀이 써 둔 템플릿 문구로 자연스럽게 넘어갑니다. 화면은 멈추지 않습니다.

## 5. AI 활용 방식

**서비스 기능**
- AI는 화면 뒤의 판독 엔진입니다. 채팅창도 자유 입력도 없고, 사용자는 탭 몇 번만 합니다. AI의 출력은 팀이 정한 JSON 스키마(structured outputs)로만 받아서 팀이 설계한 화면에 꽂습니다.
- **사실은 사람이 검증하고, 말맛은 AI가 만듭니다.** 처음에는 AI가 웹 검색으로 선수 기록을 직접 찾게 만들었습니다. 그런데 실제로 돌려보니 빠른 모델은 존재하지 않는 선수나 틀린 연도를 그럴듯하게 지어냈고, 정확한 모델은 30초 넘게 걸렸습니다. "틀린 기록이 화면에 크게 뜨는 것"이 이 서비스의 가장 큰 위험이라고 보고 구조를 바꿨습니다.
- 지금은 선수·연도·기록을 팀이 검증한 데이터에서 고르고, AI(OpenAI)는 그 사실만 받아 사용자의 나이에 맞춘 위로·동기부여·독설 문구와 운동 처방을 씁니다. 프롬프트로 "입력에 없는 사실, 숫자, 이름을 새로 만들지 않는다"를 강제했습니다.
- 서버에서 문구를 한 번 더 검사합니다(개수, 길이, 금칙어, 한국어 외 문자). 실패하거나 9초를 넘기면 템플릿 문구로 대체합니다. 웹 검색 판독 모드도 스위치로 남겨 두어, 더 좋은 모델을 쓸 수 있게 되면 바로 켤 수 있습니다.
- 독설의 과녁은 나이나 외모가 아니라 "지금 이 앱을 보고 있는 행동"으로 한정했습니다. 톤과 금지선은 모두 프롬프트로 정의했습니다.

**제작 과정**
- 기획: AI와 대화하며 주제 해석, 핵심 경험, 하지 않을 것, 리스크를 정리해 의도 문서(intent.md)와 구현 명세(spec.md)로 만들었습니다.
- 디자인: 팀 피그마 디자인 시스템(다크 + 라임 포인트)을 만들고, 컴포넌트 이름과 규격을 그대로 코드로 옮겼습니다.
- 개발: Claude Code로 명세를 기준 삼아 화면, API, 프롬프트, 검증 로직을 함께 구현했습니다.

## 6. 사용한 기술 스택 및 인프라

**기술 스택**
- Next.js 16 (App Router)
- React 19
- TypeScript
- Tailwind CSS 4
- OpenAI API (`openai` SDK, Responses API, gpt-4o-mini)
- zod (AI 응답 structured outputs 스키마와 검증)
- html-to-image (선수 카드 PNG 저장)
- Remix Icon (`@remixicon/react`)
- Figma (디자인 시스템)

**인프라 구성**
- Vercel 배포 (정적 화면 + 서버리스 API 라우트 `/api/judge`)
- OpenAI API 키는 서버 환경 변수에만 두고 브라우저에 노출하지 않습니다.
- DB, 로그인 없음. 상태는 브라우저 메모리에만 둡니다.
