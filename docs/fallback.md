# fallback.md — 비상용 결과

> AI 판독이 실패했을 때(타임아웃 25초, 네트워크 오류, 한도 초과, 거절, 검증 실패) 쓰는 데이터.
> 구현 위치: `lib/fallback.ts` (서버와 클라이언트가 같은 데이터를 쓴다). 규격은 `spec.md` 7.7.

## 0. 사용 전 필수: 팀 검증

- 아래 기록은 **널리 알려진 이정표만 골랐지만 아직 검증하지 않았다.** 모든 항목이 `verified: false`다.
- 담당자는 각 항목의 **출생 연월일, 사건 연월, 사건 당시 나이**를 위키백과나 나무위키로 확인하고 `verified: true`로 바꾼다.
- 하나라도 틀리면 고치지 말고 **지운다.** 나이 폴백이 빈자리를 메운다.
- 배포 전 `verified: false`가 남아 있으면 그 항목은 코드에서 제외한다.

## 1. 어떤 상황을 덮는가

| 상황 | 대응 |
| --- | --- |
| 가장 흔한 입력: 행사 참가자와 심사위원 나이 (20~35세) | 종목마다 18~35세 구간에 기록을 촘촘히 둔다 |
| 어린 나이 (10~17세) | 가장 어린 기록 + "당신보다 N살 많은 M세에…아직 N년 남았습니다" 문구 |
| 많은 나이 (36~60세) | 장수 기록(르브론 35세, 메시 35세, 최정 37세, 이동국 38세) + 가장 가까운 기록 |
| e스포츠 + 29세 이상 | 선수 나이대가 낮아서 "당신보다 N살 어릴 때" 문구로 처리 |
| "아무거나" | 6종목 전체 기록에서 고른다 |
| 같은 사용자가 다시 함 | `excludeAthletes`에 있는 선수는 건너뛰고, 다 막히면 무시한다. 판독 횟수(`visit`)가 늘수록 더 넓게 고른다 |

## 2. 선택 규칙

```
pool = sport === 'any' ? 전체 peaks : 해당 종목 peaks
pool -= excludeAthletes (비면 원래 pool)
// visit = 이 브라우저에서 이전에 판독한 횟수 (localStorage, lib/history.ts)
famePenalty = max(0, 3 - visit)          // 처음엔 fame 2 선수를 3살 더 먼 것처럼 취급
spread      = visit === 0 ? 0 : min(visit + 1, 4)
cost  = |eventAge - age| + (fame === 2 ? famePenalty : 0)
후보  = cost <= 최소 cost + spread 인 기록
가중치 = (fame 1이면 2, 아니면 1) / (1 + cost - 최소 cost) 로 랜덤 1개 → reveal
// 첫 방문: 나이가 가장 가까운 슈퍼스타. 재방문할수록 ±4살, fame 2 선수까지 섞인다
delta = eventAge - age
headline = 템플릿(delta)        // spec.md 5절 "delta별 리빌 문구"와 같은 규칙, 조사는 josa()
comfort  = 해당 종목 comfort 중 |lowAge - age| 가 가장 작은 것
motivate = 해당 종목 motivate 랜덤
roast    = 공통 독설 풀에서 3개 랜덤 (reveal 선수 이름 치환)
workout  = 해당 종목 workout
sources  = []                   // 비상용은 출처 링크를 띄우지 않는다
confidence = 'high'
```

`headline` 템플릿에서 `{fact}`는 아래 표의 "기록" 문구다. 예: delta = 0 → `손흥민은 당신 나이에 챔피언스리그 결승에 선발로 나섰습니다.`

## 8. 코드로 옮길 때

- 위 표를 `lib/fallback.ts`의 배열로 옮긴다. 형태는 `spec.md` 7.4 `JudgeResult`의 각 부분과 맞춘다.
- `eventYear - birthYear - eventAge`가 0 또는 1인지 서버 검증 함수(`validate.ts`)로 한 번 돌려본다. 비상용 데이터도 같은 검증을 통과해야 한다.
- 비상용 결과가 나간 횟수와 이유를 서버 로그로 남겨, 심사 중 AI가 얼마나 실패하는지 확인한다.
